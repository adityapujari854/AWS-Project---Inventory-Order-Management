# Private S3 product images

InventoryHub stores only stable S3 object keys and metadata (`image_key`, content type, size, and update time) in the database. Product image binaries and presigned URLs are never stored there.

## Bucket setup

Create a bucket in the same Region as the future application. Keep **Block Public Access** enabled and enable default SSE-S3 encryption. The application displays images by generating a short-lived presigned `GetObject` URL; the bucket and objects stay private.

Set these environment values locally or on the future EC2 instance:

```text
AWS_REGION=ap-south-1
S3_BUCKET_NAME=replace-with-private-bucket-name
S3_PRODUCT_IMAGE_PREFIX=product-images
S3_PRESIGNED_URL_TTL_SECONDS=900
S3_MAX_IMAGE_SIZE_BYTES=5242880
```

For local development, use `aws configure` with an AWS CLI profile or another standard AWS credential-provider-chain source. Do not put access keys in `.env` or source code. On EC2, attach the policy below to the instance role instead.

## Least-privilege IAM policy

Replace the placeholder bucket name and prefix before use.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ManageInventoryHubProductImages",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::replace-with-private-bucket-name/product-images/*"
    }
  ]
}
```

No public-read ACL, broad bucket administration, or `ListBucket` permission is required for the implemented operations.

## Optional catalogue bulk upload

Local catalogue images remain the default and require no AWS configuration. After running
`python scripts/download_catalogue_images.py` and
`python scripts/verify_catalogue_images.py`, inspect the non-destructive dry run:

```text
python scripts/upload_catalogue_images.py
```

Only manifest-validated files are considered. The command skips products with an existing
user-uploaded `image_key`, never deletes objects, and never overwrites an existing
`product-images/catalogue/<SKU>.<extension>` object. Add `--confirm` only after reviewing
the summary. Credentials come from the standard AWS credential provider chain.

## Image lifecycle

- Uploads accept JPEG, PNG, and WebP only after extension, declared media type, size, and file-signature checks.
- Object keys are generated by the server under the configured prefix.
- Replacements upload a new object, save its key, then attempt to remove only the previous stored key.
- Removing an image deletes only the object key associated with that product.
- Archiving a product preserves its current image for audit/history but prevents upload, replacement, and removal. There is no product deletion endpoint yet.
- If S3 configuration or AWS access is unavailable, ordinary product operations continue; image operations return a safe error.
